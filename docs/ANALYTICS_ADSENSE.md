# Google Analytics & AdSense — setup and go-live

What the code already does, and the steps only you can do (they need real IDs and
account access).

---

## 1. Google Analytics (GA4)

**In the code:** measurement ID `G-86BFQ6G0VR` is loaded by the gtag snippet at the
bottom of `index.html`. It is skipped on `localhost`, so development traffic never
reaches the property. `src/hooks/usePageTracking.js` sends a `page_view` on every
client-side route change, mounted once as `<Analytics />` in
`src/routes/AppRouter.jsx` — without it GA would only ever record the page a
visitor landed on, because a React Router navigation is not a page load.

**Nothing to configure.** To verify after a deploy: open the site, then GA →
Reports → **Realtime**, and click through two or three pages. Each one should
appear as its own page view. If nothing appears at all, an ad blocker on your own
browser is the first thing to rule out — most block gtag.

## 2. Google Search Console

Worth doing before AdSense; it is how you find out whether Google can actually
index the site.

1. search.google.com/search-console → add property → URL prefix
   `https://www.sahlearn.com`.
2. Verify by the Google Analytics method (works once step 1 is live) or by DNS.
3. Submit the sitemap: `https://www.sahlearn.com/sitemap.xml`.

The sitemap is generated by the API (`sahlearn-api/src/app.js`) from published
courses and posts plus the static pages, and proxied by the
`/sitemap.xml` rewrite in `sahlearn-web/vercel.json`. Its base URL comes from the
first entry of the API's `CORS_ORIGIN` — if the sitemap shows the wrong host, fix
`CORS_ORIGIN` on Render, not the code.

## 3. AdSense

**In the code:** publisher ID `ca-pub-1503199816496831` is live in three places —
the `google-adsense-account` meta tag and the loader `<script>` in the `<head>` of
`index.html`, `src/components/common/AdSlot.jsx`, and `public/ads.txt`. It is a
public value (every ad request carries it), so it is committed rather than left to
an env var a deploy could forget. Both head tags are static HTML, not injected by
script, because the reviewer has to find them in the served page. `AdSlot` returns
`null` until it is given a slot ID, so no ad renders anywhere until you place one
after approval.

`public/app-ads.txt` holds the same line for the future mobile app
(`docs/MOBILE_ROADMAP.md`); AdMob reads that filename, AdSense reads `ads.txt`.

**Before you apply:**

- `/privacy` and `/terms` are live and linked in the footer. AdSense reviewers
  check for a privacy policy that mentions third-party advertising cookies; both
  pages exist for that reason.
- Have real content. A thin site is the most common rejection: publish a number of
  genuine blog posts and make sure the course pages are filled in.
- Check that the About and Contact pages give a real way to reach you.

**Your steps:**

1. adsense.google.com → add site `sahlearn.com`. The publisher ID is already in
   the code, so no env var and no `ads.txt` work is left — both ship with this
   deploy.
2. Confirm both are live after deploying:
   - `https://www.sahlearn.com/ads.txt` → the `pub-1503199816496831` line
   - view-source on the home page → the `google-adsense-account` meta tag and the
     `adsbygoogle.js` script tag in the `<head>`
3. In AdSense, hit **Request review**. Approval usually takes days, sometimes
   longer.

**After approval — placing ads:**

1. AdSense → Ads → By ad unit → create a **Display ad** unit → copy its slot ID
   (a ~10-digit number).
2. Drop it into a page:

   ```jsx
   import AdSlot from '../../components/common/AdSlot';

   <AdSlot slot="1234567890" />
   ```

   Good places: between the article body and the related posts on
   `pages/public/BlogDetail.jsx`, and partway down the list on
   `pages/public/Blog.jsx`.

**Never place ads on:** `/admin/*`, `/student/*`, `/receipt/:token`, or the quiz
while a question is on screen. Ads next to a login form or an exam question breach
AdSense placement policy, and `robots.txt` already disallows the admin and receipt
paths.

## 4. Consent

Nigeria has no GDPR-style consent requirement, so no cookie banner is shipped. If
you start drawing real EU traffic, AdSense requires a consent solution — its
built-in Privacy & messaging → GDPR message is the cheapest route, and it needs no
code change.
